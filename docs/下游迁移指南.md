# 下游迁移指南：`governed.db` v2（双账号 + `account` 维度）

> **读者**：消费 `wechat_database_governance/output/governed.db` 的 agent（如 `digital_twin`）。
> **状态**：v2 构建脚本已落地；`build_meta` 表仅用于增量构建，**下游查询可忽略**。
> 消费方只需改业务表查询（加 `account`）；日常更新 governed.db 用 `build_governed_db.py --incremental`。

---

## 1. 变更摘要

| 项 | v1（旧） | v2（新） |
|----|----------|----------|
| 数据源 | 单解密库 | **两号合并**：`wechat-decrypt-personal` + `wechat-decrypt-work` |
| 账号标识 | 无（隐含单号） | 全表新增 **`account`**：`personal` / `work` |
| 号主 wxid | 不存库 | 仅在构建配置 `ACCOUNTS` 中维护，**不进 governed.db** |
| `contacts` PK | `username` | **`(account, username)`** |
| `chatrooms` PK | `username` | **`(account, username)`** |
| `chatrooms` 群主列 | `owner_username` | **`group_owner`**（避免与账号维度混淆） |
| `chatroom_members` PK | `(room_username, member_username)` | **`(account, room_username, member_username)`** |
| `messages` 去重键 | `server_id`（全局） | **`(account, server_id)`** + **`(account, chat_username, local_id)`** |
| 引用 JOIN | `o.server_id = q.reply_to` | **`o.account = q.account AND o.server_id = q.reply_to`** |
| 媒体回查 | 固定一个 `decrypted/message/` | 先按 **`account`** 选目录（见 §3） |

## 2. 账号配置（构建脚本，不进库）

```python
# accounts.local.py（本地，勿提交；见 accounts.local.example.py）
ACCOUNTS = [
    {
        "account": "personal",
        "owner_wxid": "wxid_personal_owner",   # 仅用于识别「我」、不写进表
        "decrypted_dir": "/path/to/wechat-decrypt-personal/decrypted",
    },
    {
        "account": "work",
        "owner_wxid": "wxid_work_owner",
        "decrypted_dir": "/path/to/wechat-decrypt-work/decrypted",
    },
]
```

| account | 含义 | 号主 wxid（配置占位） | 消息量（粗估） |
|---------|------|----------------------|----------------|
| `personal` | 个人号 | `wxid_personal_owner` | ~307 万 |
| `work` | 工作号 | `wxid_work_owner` | ~3 万 |

**重叠数据不合并**：82 个 `username` 在两号各一行（备注/标签/好友关系可能不同）。

## 3. v2 表结构（最终）

```
contacts(account PK, username PK, type, is_friend, ...)

chatrooms(account PK, username PK, group_owner, announcement, announcement_time)

chatroom_members(account PK, room_username, member_username,
                 PK(account, room_username, member_username))

messages(id PK, account, chat_username, local_id, server_id, timestamp,
         sender_username, is_self, type, content, media_ref, reply_to, reply_quote)
  UNIQUE (account, server_id) WHERE server_id != 0
  INDEX (account, chat_username), INDEX (reply_to)
```

字段 **`group_owner`** = 群主 wxid（源 `chat_room.owner`）。**不要**与 `account`（数据归属哪个微信号）混淆。

## 4. 查询模式迁移

### 4.1 所有表：必须带 `account`

```sql
-- ❌ 旧（v1）
SELECT * FROM contacts WHERE type = 'person' AND is_friend = 1;

-- ✅ 新（v2）— 个人分身通常只用 personal
SELECT * FROM contacts
WHERE account = 'personal' AND type = 'person' AND is_friend = 1;
```

### 4.2 会话 / 消息

```sql
-- 某号、某会话的全部消息
SELECT * FROM messages
WHERE account = 'personal' AND chat_username = 'wxid_friend_example'
ORDER BY timestamp;

-- 我发的（sender_username 仍为 'me'，但必须 scoped 到 account）
SELECT * FROM messages
WHERE account = 'personal' AND is_self = 1;
```

### 4.3 引用自关联

```sql
SELECT q.content AS my_reply,
       COALESCE(o.content, q.reply_quote) AS quoted
FROM messages q
LEFT JOIN messages o
  ON o.account = q.account
 AND o.server_id = q.reply_to
 AND o.server_id != 0
WHERE q.account = 'personal' AND q.type = 'quote';
```

### 4.4 JOIN contacts

```sql
SELECT m.*, c.remark, c.nick_name
FROM messages m
JOIN contacts c
  ON c.account = m.account AND c.username = m.chat_username
WHERE m.account = 'personal';
```

### 4.5 媒体回查

```python
MEDIA_DIRS = {
    "personal": Path(".../wechat-decrypt-personal/decrypted/message"),
    "work": Path(".../wechat-decrypt-work/decrypted/message"),
}
# row["account"] → MEDIA_DIRS[row["account"]] / "media_0.db" ...
```

## 5. `digital_twin` 建议改动清单

> 路径相对于 `digital_twin/` 仓库根。

| 模块 | 文件 | 改动要点 |
|------|------|----------|
| M01 圈层 | `circle/build_circles.py` | 读 `governed.db` 时加 `WHERE account = ?`（配置默认 `personal`）；好友/群过滤仍保留 `NOT LIKE '%@chatroom'/'%@im.chatroom'` |
| M01 圈层 | `circle/stats.py`, `circle/tier_infer.py` | 统计与 infer 输入 scoped 到单一 `account` |
| M02 风格 | `style_cards/build_style_cards.py`（如有） | 消息抽样加 `account` |
| M08 评测 | `evaluation/sampling.py` | 抽样消息加 `account` |
| M10 KB | `kb/build_kb.py`, `kb/store.py` | 入库字段增加 `account`；检索默认过滤 |
| Debug | `debug/queries.py`, `debug/rebuild.py` | UI/CLI 可选 account；重建链路传 account |
| 配置 | `config/circles.yaml` 或新建 `config/accounts.yaml` | 增加 `governed_account: personal`（工作号分身另配 `work`） |

**I1（@im.chatroom 误标 person）**：上游 `derive_type` 已支持 `@im.chatroom`；v2 重建后下游可保留防御过滤，但不应再依赖它掩盖上游错误。

**默认策略建议**：
- 个人数字分身 → **`account='personal'`** 全链路默认。
- 若要做工作号分身 → 复制 pipeline，改配置为 `account='work'`。
- **不要**在无 `account` 条件下对 v2 库做全表扫描（会混两号数据）。

## 6. 衍生库（circles.db / kb.db）是否加 `account`

| 方案 | 说明 |
|------|------|
| **A（推荐，最小）** | 衍生库仍单账号一份：配置指定 `account`，路径如 `output/personal/circles.db` |
| B | 衍生库表也加 `account` 列，一个文件存两号 |

当前 `digital_twin` 若只服务个人分身，**方案 A** 即可：配置里写 `account: personal`，无需改 circles 表结构。

## 7. 验收检查（v2 构建完成后）

```sql
-- 两号都有数据
SELECT account, COUNT(*) FROM messages GROUP BY account;
-- 期望：personal ~3e6, work ~3e4

-- 无 type 与后缀不一致（构建脚本 validate_contact_types）
SELECT account, username, type FROM contacts
WHERE (username LIKE '%@chatroom' OR username LIKE '%@im.chatroom') AND type != 'chatroom';
-- 期望：0 行

-- server_id 跨号碰撞存在但不破坏唯一约束
SELECT server_id, COUNT(DISTINCT account) FROM messages
WHERE server_id != 0 GROUP BY server_id HAVING COUNT(DISTINCT account) > 1
LIMIT 5;
-- 允许有结果；同一 (account, server_id) 仍唯一
```
